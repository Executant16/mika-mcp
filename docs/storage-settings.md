# 自定义正式数据目录

正式程序使用系统默认用户数据目录，不把个人的 D 盘路径写进安装包。需要改址时，在“设置 → 常规 → 数据与存储”查看实际目录，点击“更改位置”，选择空目录；例如个人机器可选 `D:/Lenovo/Documents/Mika-Data/production/profile`。源码开发版显示独立开发目录，但不开放正式数据迁移。

确认框显示来源、目标、文件数和估计大小，清单检查在后台线程执行，不阻塞设置窗口。请先保存工作、停止长任务，再确认。后台停止服务并刷新浏览器存储，排队后正常退出；重启后先进入独立启动窗口，由后台线程复制并校验 profile 和长期记忆，校验成功才写入新位置。窗口显示扫描、复制、校验、提交等阶段及已处理文件数/大小；总量未知时不显示虚假的百分比。正常浏览器 Session 和数据服务在这一步不会加载。迁移后 userData/sessionData 同根，记忆归入 memory-v1，临时文件与崩溃转储也使用新根。安装程序和项目 `.coding-tools/` 不移动。

定位配置位于系统用户配置目录 `Mika/storage/production.json`（Windows 通常在 `%APPDATA%` 下），只记录路径及迁移状态，不存账号、Token、Cookies 或记忆正文。它是重启后找到自定义根所必需的小文件，不修改全局环境变量。

## 保留与失败恢复

- 原 profile 与原外部记忆保留，不删除。旧 PID、运行指纹、runtime-state.json 及其备份、runtime-workspace 和浏览器单实例锁不带入新环境；它们继续留在原目录供诊断。
- 目标非空、路径重叠、包含链接/特殊文件、位于当前项目或安装目录、空间不足等情况会拒绝迁移。恢复默认是特例：默认位置已有内容时先改名为同级 `.before-switch-<迁移ID>` 备份，不覆盖旧数据；当前自定义来源仍保留。
- 复制校验失败或迁移中断不提交新根，保留 stage 与错误记录，继续使用仍可用的原根。设置页会显示失败信息；修复问题后可重选空目录。stage 和备份不自动清理。
- 已选新根失踪、不可写、变为空目录，或定位文件损坏时，不加载正常业务界面，进入独立恢复窗口。活动 profile 必须有有效 settings.json 或其既有备份，不能将空目录当作原数据。可选择已有 profile（恢复选择要求有有效 settings.json），再选择已有长期记忆目录；两次确认后备份原定位文件并写入恢复路径，再重启。此操作不复制或清空所选数据。
- 如果该 profile 原本未使用长期记忆，必须显式勾选“允许新建记忆子目录”；没有这个确认就不新建空记忆。恢复窗口不提供创建空 profile 的操作。旧 Runtime/Tunnel 仍存活或路径包含链接时拒绝恢复。
- 迁移失败但原目录仍可用时，先显示错误，用户确认后可以继续进入原环境；无法确认任何可用来源时只能选择已有数据恢复或退出，不猜测其他根。
- 同一 Windows 用户下保留加密凭据与浏览器文件的原字节，不导出明文密钥。文件校验不等于第三方网站登录状态验证，网站仍可能要求重新登录。不要用这套流程把凭据迁移到另一台机器或另一个用户。

## 本轮验证边界

使用仓库 tmp 内人工 profile、会话样本与外部记忆测试了复制校验、重新加载定位配置、恢复默认、失败与中断保留，以及路径/空间/活进程防护。真实 Node Worker 测试覆盖迁移阶段与进度推送、恢复定位及异步清单；启动窗口、重启调度和 IPC 使用模拟测试。没有安装正式版、迁移真实数据、解密真实凭据或读取真实 Cookies。当前禁止原生 UI 验收，因此完整 Electron 退出/重启、界面布局及真实网站登录恢复仍需实机验收。

启动恢复窗口使用 `<appData>/Mika/storage-ui-runtime/session-*` 下的独立诊断运行目录与非持久分区，不打开原 profile 的浏览器会话。Windows 下这个小型诊断目录可能仍在 C 盘；它不存放正式记忆和登录数据，不影响自定义数据根。运行目录及恢复备份保留供排障，本轮不自动清理。
