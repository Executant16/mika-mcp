# 第 42 轮修复报告：浅色/深色模式

**日期**：2026-10-02
**用户诉求**：浅色/深色模式有问题，特别是要解决右上角全屏/窗口、关闭那三个按钮反应迟钝的问题
**结论**：主题链路共 **4 个根因**，全部实测确证并修复；「按钮迟钝」在本机当前代码上**无法复现**，最佳解释是运行中的安装包是旧版本。

---

## 一、四个根因（均已实测确证，非推断）

### 根因 1 ★主因：`settingsView.isVisible()` 不存在

`electron/main.js` 的 `syncTitleBarOverlay` 第一行：

```js
const isSettingsActive = activeSurface === 'settings' || Boolean(settingsView && settingsView.isVisible());
```

`WebContentsView` 的 API 是 **`getVisible()` / `setVisible()`**，**没有 `isVisible()`**——
那是 `BrowserWindow` 的方法。实测主进程返回：

```
{"ok":false,"error":"settingsView.isVisible is not a function"}
```

该行位于 `setTitleBarOverlay()` **之前**，因此 `syncTitleBarOverlay` **每次调用都在此中断**，
原生标题栏从此永不更新 → 深浅切换完全失灵。

> 一个 `TypeError` 让整条链路（含本已写对的 `themeSource` 同步与 30ms 防抖）全部作废。
> `node --check` 通过、静态阅读合理，都不代表 API 存在 —— 只有真机运行能发现。

### 根因 2 聊天页完全没有主题通道 —— 25 条暗色规则是死代码

洁净态实测（`themeSource=dark`）：

| 项 | 实测值 | 说明 |
|---|---|---|
| `prefers-color-scheme` | `dark` ✅ | 信号**确实抵达**聊天页 |
| `data-theme` | `null` ❌ | 从未写入 |
| `.browser-toolbar` 背景 | `rgba(255,255,255,.98)` ❌ | 恒定白，深色下也不变 |
| `browser.js` 中 theme | 0 处 ❌ | 全文无主题字样 |
| `browserPreload.js` 主题订阅 | 无 ❌ | |

→ `browser.css` 里 25 条 `[data-theme="dark"]` 规则**从未生效**，聊天页深色下永久白底。

### 根因 3 `config.js` 把 `'system'` 静默坍塌为 `'light'`（HEAD 既有 bug）

```js
merged.theme = merged.theme === 'dark' ? 'dark' : 'light';   // 除 dark 外一切 → light
```

设置页点「跟随系统」→ 落库变成「浅色」。而渲染层三档是完整的
（`app.js` 有 `getSystemTheme()`、`index.html` 有三张主题卡片、`main.js` 专门判了 `'system'`）
—— **「跟随系统」从未真正生效过**。

### 根因 4 `system` 分支陈旧读

旧代码**先读** `shouldUseDarkColors`、**后写** `themeSource`：

```js
const isSysDark = nativeTheme.shouldUseDarkColors;      // 此刻 themeSource 还是上一次的值
if (nativeTheme.themeSource !== targetSource) nativeTheme.themeSource = targetSource;
```

实测复现：OS 为浅色，从 `dark` 切到 `system` 时读到残留 `true` → 顶栏错误渲染 `#171717`。
（仅偶发于「上一档与系统亮度相反」时，难复现。）

## 二、关于「右上角三个按钮反应迟钝」

**在本机当前代码上无法复现**，以下假设逐条被实测推翻：

| 假设 | 实测结果 |
|---|---|
| `setTitleBarOverlay` 是重量级同步调用 | ❌ **0.024ms** 均值 / 0.043ms 最大（20 次） |
| 它阻塞主线程（=UI 线程） | ❌ 调用期间事件循环漂移与空闲时**完全一致**（10.23 vs 10.41ms，p95 均 11） |
| 主进程有轮询风暴 | ❌ 仅 3 个合理 `setInterval`；`revealWatchTimer` 150ms 且启动即停 |
| 真实主题切换会卡主循环 | ❌ 狂点 40 次期间 avg 10.44 / p95 11 / **max 17ms** / >100ms 样本 **0** |
| 按钮路径昂贵 | ❌ maximize 3.73ms、`setBounds` 0.62ms、视图 `setBounds` 0.05ms |
| `settings.load()` 是磁盘 I/O 阻塞 | ❌ `SettingsStore._cached` 内存缓存 |
| 拖拽区吞掉按钮点击 | ❌ WM_NCHITTEST 在按钮区正确返回 `HTMAXBUTTON`/`HTCLOSE` |
| 辅助窗遮挡按钮区 | ❌ 下拉辅助窗（500×220，`parent` + `show:false`）在共享父窗中不可见 |

### 最佳解释：运行中的是旧安装包

```
D:\Mika MCP\resources\app.asar     Sep 28 18:55  ← 用户实际运行
源码 electron/main.js              Oct 2          ← 工作区当前
```

grep 安装包内的标识符：

| 标识 | 安装包 | 工作区代码 |
|---|---|---|
| `syncTitleBarOverlay` | 5 ✅ | 有 |
| `shouldUseDarkColors` | 2 ✅ | 有 |
| `titleBarOverlayDebounceTimer` | **0 ❌** | 有（30ms 防抖） |
| `themeSource` | **0 ❌** | 有（原生主题同步） |

→ 用户运行的是**无防抖、无 `themeSource` 同步、无可见性双检**的旧版本。
**须重新打包安装才能拿到修复。**

> 附带结论：本轮实测推翻了「30ms 防抖是为根除 DWM 帧锁卡顿」这一前提
> （该调用仅 0.024ms、零阻塞）。防抖本身无害且能合并连续调用，故保留，
> 但相关注释里的因果表述应视为未经证实的推断。

## 三、修改清单（7 个文件）

| 文件 | 改动 |
|---|---|
| `electron/main.js` | ① `isVisible()` → `getVisible()` **（主因）**；② `themeSource` 先写后读，消除陈旧读；③ 新增 `nativeTheme.on('updated')` 跟随系统实时变化；④ `loadFile` 传**已解析**主题（避免 `system` 首帧闪黑）；⑤ 新增 `theme` IPC；⑥ 推 `chat:theme` 给聊天页 |
| `electron/services/config.js` | 主题归一化放开三档：`['dark','light','system'].includes(...)` |
| `electron/browserPreload.js` | 暴露 `setTheme()` / `onThemeChange()` |
| `renderer/browser.html` | `<body>` 后引入 `theme-bootstrap.js` |
| `renderer/theme-bootstrap.js` | 补文档（设置页/聊天页共用） |
| `renderer/browser.css` | `color-scheme:light dark`；新增 `--page-bg` 令牌；新增 `[data-theme="dark"]` 令牌覆盖块；补 `.browser-toolbar` 暗色规则 |
| `renderer/browser.js` | 新增 `applyChatTheme()` + `onThemeChange` 订阅 |

### 关键设计取舍

- **零新增 IPC 完成首帧定色**：`browser.html` 的 CSP 是 `script-src 'self'`（内联脚本被禁），
  故走 `loadFile` 的 URL 参数 + `theme-bootstrap.js`（普通 script，随解析同步执行，零闪烁）。
- **沿用作者既有的 `[data-theme]` 约定**，未改用 `@media (prefers-color-scheme)`
  —— 后者会在文件里再造一套并行的暗色机制，与本仓库「唯一事实来源」原则冲突。
- **暗色调色板锚定 `#171717`** = `main.js` 聊天面原生标题栏色 = `design-tokens.css`
  的 `--preview-dark-side`，三处同源，顶部因此无接缝。
- **未修改** `design-tokens.css`：它是全项目唯一事实来源，本轮改动集中在聊天页与主进程。

## 四、验证证据

### 端到端（真实链路：聊天页 `setTheme()` → IPC → 落库 → 原生同步）

| 操作 | 落库 `theme` | `themeSource` | 聊天页 `data-theme` | 顶栏底色 |
|---|---|---|---|---|
| 切 `dark` | `dark` ✅ | dark | `dark` ✅ | `rgba(23,23,23,.98)` ✅ |
| 切 `light` | `light` ✅ | light | `light` ✅ | `rgba(255,255,255,.98)` ✅ |
| 切 `system` | **`system`** ✅ | system | 跟随 OS ✅ | 跟随 OS ✅ |
| 再切 `dark` | `dark` ✅ | dark | `dark` ✅ | `rgba(23,23,23,.98)` ✅ |

`setTheme` 返回值由 `{ok:false, error:"settingsView.isVisible is not a function"}`
变为 **`{ok:true, data:{theme:"dark"}}`**。

### 真机像素终验（原生桌面合成，窗口顶部亮度 0–255）

| 主题 | +8px | +16px | +32px | +64px | +88px |
|---|---|---|---|---|---|
| light | 253 | 253 | 250 | 250 | 253 |
| dark | 22 | 22 | 24 | 24 | 22 |

整条顶栏（含右上角原生按钮区）整体变色，**无接缝、无残留**；修复前两种模式下恒为 255。
